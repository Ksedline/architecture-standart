### Название задачи: Передача актуальных депозитных ставок во внутренний и партнёрский кол-центры (MVP)
### Автор: Команда цифровой трансформации
### Дата: 04.07.2025

### Функциональные требования (Use Cases)
| № | Действующее лицо / система         | Сценарий |
|:-:|------------------------------------|----------|
| 1 | Бэк-офис депозитов                | Подтверждает/изменяет ставку в АБС, инициирует обновление ставок |
| 2 | Rate Service                      | Получает событие об изменении ставки из АБС, публикует событие RateChanged |
| 3 | Сервис передачи ставок (новый)    | Получает событие, отправляет ставки во внутренний кол-центр (REST) и формирует CSV для партнёрского кол-центра (SFTP) |
| 4 | Кол-центр                         | Принимает ставки по REST, обновляет справочник ставок для операторов |
| 5 | Партнёрский кол-центр             | Периодически читает CSV с SFTP, обновляет справочник ставок |

### Нефункциональные требования
| № | Требование |
|:-:|------------|
| 1 | Максимальная задержка доставки ставки до обоих кол-центров — не более 60 секунд |
| 2 | Доступность сервиса передачи ставок — не ниже 99,9% |
| 3 | Все каналы защищены: REST — HTTPS/TLS 1.2+, SFTP — SSH v2, проверка fingerprint |
| 4 | Минимум 3 попытки повторной доставки при сбоях (retry с экспоненциальной задержкой) |
| 5 | Ведение аудита всех попыток доставки ставок (хранение не менее 1 года) |
| 6 | Использование только утверждённого техстека банка: Java, Spring Boot, RabbitMQ, MS SQL/Oracle |
| 7 | Прямых вызовов кол-центр → АБС нет |

### Архитектурное решение
- Все изменения ставок инициируются в АБС (Delphi + Oracle), далее событие поступает в Rate Service (Java), который публикует событие RateChanged в RabbitMQ.
- Новый сервис передачи ставок (Java/Spring Boot) слушает события RateChanged, отправляет ставки во внутренний кол-центр по REST (PUT /rates), а для партнёрского кол-центра формирует CSV и выгружает на SFTP.
- Внутренний кол-центр обновляет справочник ставок для операторов автоматически, партнёрский — по cron-скрипту.
- Вся интеграция защищена (TLS, SSH), ведётся аудит всех попыток доставки.

### Альтернативы
- Встроить REST-API ставок прямо в платформу кол-центра — не подходит, так как партнёрский кол-центр требует файл, а открытый API увеличивает риски.
- Делить таблицу Oracle через DB-link — нарушает принцип «одна БД — один владелец», увеличивает риски безопасности и нагрузки.
- Отправлять Excel-файл по e-mail — ручная обработка, задержки, высокий риск ошибок.

### Недостатки и риски
- Зависимость от SFTP-канала: нет SLA у партнёра, возможны простои.
- Формат CSV жёстко фиксирован: любые изменения требуют согласования.
- RabbitMQ выбран для быстрого старта, при переходе на Kafka потребуется миграция.
- Если ставка отозвана/исправлена после выгрузки — требуется отдельное событие, иначе в кол-центре останется устаревшая ставка.

|----------------------------------|-----------------|
| АБС (DB-team)                    | PL/SQL-триггер для отправки notify, обработка отмены ставки |
| Rate Service (Java-team)         | Подписка на notify из АБС, публикация события RateChanged (RabbitMQ) |
| Сервис передачи ставок (новый)   | Создание сервиса, реализация компонентов (Listener, REST push, CSV, SFTP), аудит, метрики |

| Партнёрский кол-центр (внешний)  | Cron-скрипт для чтения CSV, обновление UI ставок |
| DevOps                           | Кластер RabbitMQ, SFTP, Vault для ssh-key, мониторинг доставки |
| Security                         | Проверка threat-model, регламент аварийного переключения |
